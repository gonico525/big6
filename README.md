# プリズナートレーニング継続アプリ

BIG6 の実施を継続するための個人用 Web アプリ。起動した時点で「今日やること」が確定表示され、
実行の完了が最小操作で記録される。記録アプリではなく実行アプリとして作っている。

仕様書: [`docs/spec/prisoner-training-app-spec-v0.4.md`](docs/spec/prisoner-training-app-spec-v0.4.md)

## 使い方

### 初回セットアップ

1. アプリを開く（ローカルなら `npm run serve` → http://localhost:8000）
2. 設定 →「現在のステップ・級」で 6 種目の現在地を入力する
3. 必要なら 設定 →「ステップマスタ」で基準値・ステップ名を書籍の版に合わせて直す

ステップマスタは `standards.json` に入っている値が初回起動時に読み込まれる。
すでに起動したあとで `standards.json` を差し替えた場合は、
設定 → データ →「ステップマスタをテンプレートから読み込む」で反映する
（実施記録と設定は残る）。

### 日々の使い方

- ホームで種目カードをタップ → 種目実行画面
- スタートでテンポカウントが始まる（毎秒ビープ、レップの先頭のみ低い音）
- 終了 → ±で実績を調整 → 記録する
- セット間は「休憩する」でカウントアップ
- 途中で離脱しても、次回起動時に「続きから／ここまでを記録／破棄」を選べる

## 画面

| 画面 | 役割 |
|---|---|
| ホーム | 今日やること（当日目標・週の実績・昇格／降格の提案） |
| 種目実行 | テンポカウント・休憩・当日の記録 |
| 進捗 | 6種目×10ステップのグリッド、履歴の閲覧・追加・修正・削除 |
| 設定 | 進み方の係数、テンポと音、ステップマスタ、エクスポート／インポート |

## ファイル構成

```
index.html
app.js          … 画面と状態管理
logic.js        … 目標算出・昇格判定・降格判定・解禁判定（DOM に触れない純粋関数）
timer.js        … テンポカウント・休憩タイマー・音生成（Web Audio API）
store.js        … 保存の抽象化（localStorage への依存をここに閉じ込める）
standards.json  … ステップマスタの初期テンプレート（名称・基準値・unit・mode・perSide）
style.css
test/           … logic.js のテスト（node:test）
docs/spec/      … 仕様書
```

## 開発

```sh
npm test        # ロジックのテスト（依存パッケージなし）
npm run serve   # 静的サーバ。http://localhost:8000
```

ビルド工程はない。ES モジュールをそのまま配信する。

## デプロイ

`main` への push で GitHub Actions が Pages へデプロイする
（`.github/workflows/pages.yml`）。

初回のみ、リポジトリの **Settings → Pages → Build and deployment → Source** を
**GitHub Actions** に切り替える必要がある。

Wake Lock API と Web Audio API を使うため、HTTPS 配信が前提。

## データ

- 保存先は `localStorage`（キー: `prisoner-training-app`）
- 端末間の移行は 設定 → データ の JSON エクスポート／インポートで行う
- アカウントもサーバ同期もない

## 実装上の判断

仕様書に書かれていない箇所について、実装で以下のように解釈した。

- **級の初期値の扱い（仕様書 4.5）**: `initialState.level` を下限として使うのは、
  その種目が `initialState.step` に在籍している間だけとした。ステップが変われば動作自体が
  変わり、アプリ導入前の到達状況は引き継げないため。
- **漸進の基準値（仕様書 4.1(c)）**: 「+maxIncrement」の基準はレコードに保存された
  `targetOfDay`（実際に提示した目標）とした。基準値を後から修正しても、過去に提示した
  目標を計算し直さないため。
- **設定からの手動変更**: `type: "manual"` のステップ変更イベントとして記録し、
  昇格直後の係数（`initialRatio`）は適用しない。手動変更は「現在地の申告」であり、
  昇格による動作の変化とは性質が異なるため。

### ステップマスタの属性

`standards.json` の `unit` / `mode` / `perSide` は、基準値の表記から次のように決めた。
いずれも設定画面から変更できる。

- **`perSide: true`**: 基準が「各◯回」と表記されるステップ
  （プッシュアップ・スクワット・プルアップ・ハンドスタンドの Step7〜10）
- **`mode: "hold"` / `unit: "sec"`**: 基準が秒数のホールドであるステップ
  （ハンドスタンド Step1〜3）
- **`mode: "free"`**: レップを 4 フェーズに分解できない動作
  （ブリッジ Step7・8 のウォール・ウォーキング）
